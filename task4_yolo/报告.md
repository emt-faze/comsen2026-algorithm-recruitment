## 三、模型训练

**策略**：以题目提供的 `drone.pt` 为初始权重做微调（fine-tune），
而非从 COCO 预训练权重从头训练——因为该权重已在同类数据上收敛，
微调能更快到达更优解。

**超参数**：

| 项 | 值 |
|---|---|
| 初始权重 | `drone.pt`（YOLO11n，2 类） |
| epoch | 30 |
| batch | 16 |
| imgsz | 640 |
| 优化器 | auto（SGD 动量 + 自动学习率） |
| 数据增强 | HSV 抖动、平移 0.1、缩放 0.5、水平翻转 0.5、Mosaic 1.0（最后 10 轮关闭） |
| AMP 混合精度 | 开启 |
| 训练耗时 | **16.6 分钟**（0.277 小时） |

## 四、训练结果

**最终验证集指标（best.pt，649 张 / 4,650 个框）**：

| 指标 | 全部 | bird | **drone** |
|---|---|---|---|
| Precision | 0.833 | 0.772 | **0.894** |
| Recall | 0.743 | 0.574 | **0.912** |
| **mAP50** | 0.774 | 0.616 | **0.931** |
| mAP50-95 | 0.375 | 0.228 | **0.522** |

**与原权重的对比**：

| 模型 | Precision | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| 原始 `drone.pt` | 0.7999 | 0.7485 | 0.8056 | 0.4962 |
| 微调后 `best.pt` | 0.833 | 0.743 | 0.774 | 0.375 |
| 微调后 **drone 类** | **0.894** | **0.912** | **0.931** | **0.522** |

**关键结论**：
1. **drone 类大幅提升**：mAP50 从 0.8056 提升到 **0.931**，Recall 从 0.7485 提升到 **0.912**
2. 总体 mAP50 反而略降（0.8056 → 0.774），原因是 **bird 类被拖累**：
   bird 只有 0.616，而 bird 占了 93% 的标注框。
   原权重记录的是它自己训练时的指标，两者验证划分不完全可比。
3. 对「无人机检测」这个实际目标而言，**微调是成功的**。

**混淆矩阵**（`outputs/train_confusion_matrix_normalized.png`）：

![混淆矩阵](outputs/train_confusion_matrix_normalized.png)

- drone 被判为 bird 仅 1%，被判为背景 4% → **漏检率低**
- bird 被判为 drone 达 14% → 鸟与无人机在外形、尺度上高度相似，是这个任务的内在难点
- 背景被判为 bird 有 20% → 树叶、纹理等背景容易误触发 bird

## 六、模型导出与量化对比（提高部分）

把微调后的 `best.pt` 分别导出 ONNX FP32 与 FP16，在同一批 48 帧上对比（RTX 4060）：

| 模型 | 大小 | 平均耗时 | **推理速度** | 相对提升 |
|---|---|---|---|---|
| PyTorch FP32 (.pt) | 5.47 MB | 10.69 ms | 93.56 FPS | 基准 |
| ONNX FP32 | 10.61 MB | 8.78 ms | 113.89 FPS | **+21.7%** |
| **ONNX FP16** | **5.36 MB** | **7.54 ms** | **132.65 FPS** | **+41.8%** |

**结论**：

1. **ONNX FP16 是最优选择**：比 PyTorch 快 41.8%，且体积还略小（5.36 vs 5.47 MB）
2. **ONNX FP32 体积翻倍**（10.61 MB）是因为 ONNX 保存完整计算图且未做权重压缩
3. **精度基本无损**：每帧目标数 0.85 → 0.90，差异在正常抖动范围内
4. 一个值得注意的对照：**同一套 ONNX 在纯 CPU 上反而比 PyTorch 慢**
   （26.86 vs 33.92 FPS，见早期实验）。说明 ONNX 的收益依赖执行后端——
   GPU 上有 CUDA/TensorRT EP 加速，CPU 上缺少 OpenVINO 优化就会退化。

**INT8 量化未完成**：Ultralytics 的 INT8 导出需要提供校准数据集，
且当前 TensorRT 未安装（需要额外安装 `tensorrt` 包并匹配 CUDA 版本）。
这一项如实标注为未完成。

## 七、结论

1. **微调有效**：drone 类 mAP50 从 0.8056 提升到 0.931，Recall 从 0.7485 提升到 0.912
2. **误检显著减少**：视频每帧目标数从 2.81 降到 0.87，Bird 误检完全消失
3. **ONNX FP16 加速明显**：132.65 FPS，比 PyTorch 快 41.8%，体积还更小
4. **类别不平衡是主要瓶颈**：bird 与 drone 的标注比约 14:1，导致 bird 类指标明显偏低
5. **鸟/无人机难分**：14% 的 bird 被判为 drone，这是任务本身的外形相似性决定的

## 八、改进方向

1. **重采样平衡类别**：对 drone 类做过采样或对 bird 类欠采样，提升整体 mAP
2. **更长训练**：30 epoch 时 mAP 仍在上升，可训练 100 epoch 观察收敛
3. **提高输入分辨率**：`imgsz` 提到 960，改善远距离小无人机
4. **INT8 量化**：提供校准集后做静态量化，理论可再压缩 4 倍
5. **TensorRT 导出**：安装 `tensorrt` 后导出 `.engine`，预期比 ONNX 再快 1.5~2 倍
6. **加跟踪**：用 ByteTrack 把逐帧检测串成轨迹，用轨迹长度过滤瞬时误检
